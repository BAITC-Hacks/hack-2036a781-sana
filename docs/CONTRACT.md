# Контракт данных и API Sana

Этот документ описывает работающие переходы между интерфейсом, FastAPI и JSON хранилищем. На экране можно переключать роли без регистрации. Право изменить задачу или действовать за команду подтверждается личным ключом, который сервер выдаёт один раз при создании записи. Интерфейс сохраняет ключ в браузере; публичные ответы не содержат ключей или их хешей.

## Данные

### Карточка задачи

Поля, нужные для кейса:

| Поле | Смысл |
| --- | --- |
| `title` | Название |
| `context` | Что происходит сейчас |
| `need` | Что нужно изменить |
| `users` | Кто будет пользоваться результатом |
| `data_materials` | Данные, примеры, материалы |
| `constraints` | Сроки, технологии, доступы и другие границы |
| `expected_result` | Конкретный результат работы команды |
| `success_criteria` | Измеримые признаки успеха |
| `contact` | Контакт бизнеса |
| `interaction_format` | Формат консультаций и обратной связи |

Дополнительные поля: `id`, `industry`, `status`, `rating`, `created_at`. После явной публикации `status` равен `published`. До неё карточка существует в браузере как редактируемый черновик и не появляется в каталоге. Сервер пересчитывает `rating` при создании и изменении опубликованной задачи.

### Рейтинг

`rating` содержит `score` (0–100), `level`, `breakdown` (получено/максимум по каждому показателю), `missing` и `tips`. Поле засчитывается, если после обрезки пробелов по краям в нём не меньше 15 символов. Это правило приложения. Для показателей из двух полей одно заполненное поле даёт половину веса.

| Ключ | Поля | Вес |
| --- | --- | ---: |
| `context_need` | `context`, `need` | 20 |
| `data_materials` | `data_materials` | 20 |
| `expected_result` | `expected_result` | 15 |
| `success_criteria` | `success_criteria` | 15 |
| `constraints` | `constraints` | 10 |
| `users` | `users` | 10 |
| `business_link` | `contact`, `interaction_format` | 10 |

`level`: `draft` для 0–39, `working` для 40–69, `ready` для 70–89, `priority` для 90–100. Баллы рейтинга задачи не складываются с баллами фактического прогресса команды.

### Команда, предложение и результат этапа

`Team`: `id`, `name`, массивы строк `interests`, `skills`, `technologies`. Каждая команда создаётся через API и получает свой ключ. Синтетические команды из `data/` используются для проверок и не появляются в новом рабочем каталоге.

`Proposal`: `id`, `task_id`, `team_id`, `idea`, `plan`, `deadline`, `link`, `status`, `created_at`. Статус `new`, `accepted` или `rejected`. Число предложений не ограничено. Бизнес может принять несколько, одно или ни одного; система не назначает команду автоматически.

`Progress`: `id`, `proposal_id`, `task_id`, `team_id`, `result`, `evidence_link`, `status`, `points` и временные метки. Этап отправляет команда с принятым предложением. Статус `submitted`, `confirmed` или `rejected`; очки начисляются только после ручного подтверждения бизнеса. В MVP подтверждённый этап даёт 10 очков. Это проектное допущение: в PDF кейса количество очков не указано.

## Право на действие

| Действие | Ключ в заголовке |
| --- | --- |
| Создать задачу или команду | Не требуется; ответ содержит новый ключ |
| Изменить задачу, прочитать её предложения, принять или отклонить предложение, подтвердить этап | `X-Sana-Owner: <owner_token>` для этой задачи |
| Отправить предложение, увидеть предложения команды, отправить результат этапа | `X-Sana-Team: <team_token>` для этой команды |
| Открыть каталог, публичную карточку, список команд и рейтинг | Не требуется |

Нужно передавать ключ ровно той записи, от имени которой выполняется действие. Ключи не отправляются в тело карточки и не включаются в публичные ответы. Переключение роли в интерфейсе меняет экран, а не право доступа. Меню «Доступ» позволяет скопировать код задачи или команды на другое устройство; без сохранённой копии утерянный код восстановить нельзя.

## Формат ответа и AI

Основные API ответы обёрнуты в один формат:

```json
{"ok": true, "data": {}}
{"ok": false, "error": {"code": "invalid_input", "message": "Понятное описание ошибки"}}
```

Приложение возвращает ошибки в теле ответа; интерфейс проверяет `ok`. Исключение — короткий `GET /api/health` с `{"status":"ok"}`.

`POST /api/analyze` принимает `draft`, `industry`, `locale` (`ru`, `kk`, `en`) и возвращает не меньше трёх объектов `{"key":"data_materials","question":"...","suggestions":["...","...","..."]}`, список `missing` и `source` (`ai` или `fallback`). Три `suggestions` — редактируемые примеры ответа, а не факты пользователя. `POST /api/build-card` принимает исходный текст, ответы и язык; возвращает редактируемую `card` и `source`. Промпты находятся в `core/prompts.py`. Ответ модели проверяется: неправильный JSON или неподходящий набор вопросов ведёт к резервным вопросам; поле карточки принимается из AI только при точной цитате из введённого человеком текста. Неизвестные сведения остаются пустыми. При `AI_MODE=fallback` обращения к OpenAI нет.

## Эндпоинты

| Метод | Путь | Действие |
| --- | --- | --- |
| `POST` | `/api/analyze` | Анализ черновика и уточняющие вопросы |
| `POST` | `/api/build-card` | Сборка редактируемой карточки из текста и ответов |
| `POST` | `/api/rating` | Расчёт рейтинга без сохранения |
| `POST` | `/api/tasks` | Публикация карточки; ответ содержит `data.task` и `data.owner_token` |
| `GET` | `/api/tasks` | Весь опубликованный каталог: `industry`, `level`, `sort=rating` или `sort=date` |
| `GET` | `/api/tasks/{task_id}` | Публичная карточка задачи |
| `PUT` | `/api/tasks/{task_id}` | Изменение и пересчёт рейтинга с `X-Sana-Owner` |
| `GET` | `/api/teams` | Публичные профили команд |
| `POST` | `/api/teams` | Создание профиля из `name`, массивов `interests`, `skills`, `technologies`; ответ содержит `data.team` и `data.team_token` |
| `POST` | `/api/tasks/{task_id}/proposals` | Предложение с `team_id`, `idea`, `plan`, `deadline`, `link` и `X-Sana-Team` |
| `GET` | `/api/tasks/{task_id}/proposals` | Предложения владельцу задачи с `X-Sana-Owner` |
| `GET` | `/api/teams/{team_id}/proposals` | Предложения своей команды с `X-Sana-Team` |
| `POST` | `/api/proposals/{proposal_id}/decision` | Ручное `accepted` или `rejected` с `X-Sana-Owner` |
| `POST` | `/api/proposals/{proposal_id}/progress` | `result`, `evidence_link` с `X-Sana-Team` после принятия предложения |
| `GET` | `/api/proposals/{proposal_id}/progress` | Отчёты этапов для владельца задачи или соответствующей команды |
| `POST` | `/api/progress/{progress_id}/decision` | Ручное `confirmed` или `rejected` с `X-Sana-Owner` |
| `GET` | `/api/progress` | Табло команд по подтверждённым очкам |
| `GET` | `/api/recommendations?team_id=...` | Дополнительная сортировка задач по совпадению интересов команды |
| `GET` | `/api/health` | Проверка сервера |

Каталог по умолчанию сортируется по убыванию `rating.score`; равные баллы сохраняют порядок добавления. `sort=date` показывает новые задачи первыми. Фильтры не скрывают задачи вне выбранного запроса из общего каталога. Задачи с рейтингом 0–39 тоже видны и принимают предложения.

## Хранение и запуск

## Расширение: аккаунты и сдача решений

По прямому запросу владельца проекта первоначальный MVP расширен регистрацией,
командами и ручной проверкой решений. Структура карточки, формула рейтинга и старые
маршруты не заменены. Новые маршруты находятся в `app/account_routes.py`, правила —
в `core/accounts.py` и `core/workflow.py`.

- `POST /api/auth/register`: `name`, `email`, `password` (10–128 символов),
  `role=business|student`; `POST /api/auth/login`: email/password.
- `POST /api/auth/logout` отзывает текущую сессию.
- `GET /api/auth/me`: `user`, `teams` (только свои, с участниками и кодом),
  `owned_task_ids`. Без сессии `user=null`.
- `PUT /api/account/profile`: `name`, `company`, `about`; роль и email неизменяемы.
- `POST /api/account/teams/{id}/invite`: капитан создаёт/заменяет шестизначный
  код на 7 дней. `POST /api/account/join`: `code`; присоединение студента.
- `GET /api/workspaces`: принятые предложения текущего бизнеса/команды, карточки,
  сообщения наставника и история решений.
- `POST /api/workspaces/{proposal_id}/submit`: `result`, `link`, `comment`.
  Только команда выбранного предложения. Версии нумеруются атомарно; новая версия
  допустима после возврата, не во время проверки и не после принятия.
- `POST /api/workspaces/{proposal_id}/review`: `version`,
  `decision=accepted|returned`, `comment`; комментарий обязателен при возврате.
  Только владелец задачи. Старые версии сохраняются. Автоматической оценки нет.
- `POST /api/workspaces/{proposal_id}/coach`: `question`; возвращает историю
  `messages`. Текущий наставник — явно обозначенный `source=fallback`: план по
  полям карточки без генерации кода/готового решения и без выдуманных фактов.
- `GET /api/notifications`: события предложений/решений; `POST
  /api/notifications/read`: `ids`. Интерфейс проверяет события каждые 15 секунд.

Новые ответы сохраняют `{ok,data}` / `{ok:false,error}`; ошибки новых маршрутов
используют HTTP 400/401/403. Cookie `sana_session`: случайный непрозрачный токен,
HttpOnly, SameSite=Strict, Secure при HTTPS, 7 дней. В хранилище только SHA-256
токена и salted PBKDF2-SHA256 пароля (600000 итераций). Записывающие запросы
требуют `X-Sana-Request: 1` и same-origin. Авторизация проверяется сервером.

Каталог и отдельная карточка остаются публичными. Рекомендации отображаются
как подсказка и больше не меняют выбранную сортировку рейтинга. Аккаунт бизнеса
связан с `owner_id`, команда — с `creator_id` и участниками. Старые записи и
bearer-токены не удаляются; они не дают доступа к новым аккаунтным записям.
Автоматического присвоения старых задач новому аккаунту нет.

`workflow.json` (или запись `workflow/accounts` в существующем PostgreSQL)
хранит аккаунты, сессии, участников, приглашения, сообщения, версии и прочтения.
JSON использует существующие файловые блокировки; PostgreSQL — транзакционную
advisory-блокировку. Это компактное MVP-хранилище, не новая БД.
`SANA_LEGACY_MODE=1` допускается только для прежних тестов/локальных демо,
по умолчанию 0. Не включать на публичном сайте.

Ограничения этой версии: нет подтверждения email и восстановления пароля;
проверки выполнялись с JSON, PostgreSQL требует отдельного интеграционного прогона;
наставник в workspace работает по правилам, существующий AI-конструктор сохраняет
свою интеграцию с моделью. Для публичной эксплуатации нужен HTTPS и постоянное
хранилище. Тестовые учётные записи не входят в репозиторий.

`core/store.py` работает с JSON в `.sana-data/`; это рабочая папка по умолчанию, она исключена из Git. `SANA_DATA_DIR` меняет её путь. Файлы в `data/` — отдельные синтетические примеры кейса для тестов и сверки, не стартовый контент реального каталога. `.env.example` содержит названия переменных без секретов. Полная инструкция запуска и повторяемый пользовательский сценарий находятся в корневом `README.md`.
