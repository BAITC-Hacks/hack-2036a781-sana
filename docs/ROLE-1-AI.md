# Участник 1 — AI и карточка задачи

Твоя папка: `core/ai.py`, `core/prompts.py`.
Ты закрываешь: качество карточки (15) + AI-функция (10) = **25 баллов**.

Что проверяют: вопросы уместны, карточка полная и редактируемая, результат AI
структурирован и **не содержит выдуманных данных**.

**Главное ограничение кейса:** AI не добавляет фактов, которых пользователь не
сообщал. Если сведений нет — поле остаётся пустым. Это проверяется на защите:
введут слабое описание и посмотрят, не дорисовала ли система подробности.

## 0:20–0:30 · Заглушка (критично)

**Промпт для Codex:**

```
Создай core/ai.py с двумя функциями по контракту из docs/CONTRACT.md:

def analyze_draft(draft: str, industry: str = "") -> dict
def build_card(draft: str, answers: list[dict]) -> dict

Пока это заглушки без вызова моделей.

analyze_draft возвращает три фиксированных вопроса с ключами data_materials,
expected_result, success_criteria, список missing и "source": "fallback".

build_card возвращает {"card": <пустая карточка со всеми полями из контракта>,
"source": "fallback"}.

Обе валидируют вход: draft должен быть непустой строкой до 4000 символов.
При некорректном входе возвращают {"error": {"code": "invalid_input", "message": ...}}.
Исключения наружу не выбрасываются никогда.
```

Коммить сразу: без этого участник 2 не может строить экран.

## 30–100 минут · Настоящий AI

### Промпты (`core/prompts.py`)

**Промпт для Codex:**

```
Создай core/prompts.py. В нём две константы с промптами.

ANALYZE_PROMPT — системный промпт для анализа черновика бизнес-задачи.
Модель должна определить, каких из семи показателей не хватает, и задать
не менее трёх уточняющих вопросов, по одному на самый важный недостающий показатель.

Семь показателей (ключи строго такие):
context_need — контекст и потребность
data_materials — доступные данные, примеры, источники
expected_result — конкретный ожидаемый результат
success_criteria — измеримые критерии успеха
constraints — сроки, технологии, доступы
users — для кого решение
business_link — контакт и формат взаимодействия

Требования к промпту:
- Отвечать строго в JSON: {"missing": ["ключ"], "questions": [{"key": "...", "question": "..."}]}
- Вопросы на русском, конкретные, без общих формулировок
- Вопрос должен спрашивать ровно об одном недостающем показателе
- Минимум 3 вопроса даже если черновик подробный
- Ничего, кроме JSON, в ответе быть не должно

BUILD_CARD_PROMPT — системный промпт для сборки карточки.
Модель получает черновик и ответы пользователя, раскладывает их по полям карточки.

Требования к промпту, выделить их явно как запреты:
- ЗАПРЕЩЕНО добавлять факты, которых нет в черновике или ответах
- ЗАПРЕЩЕНО додумывать сроки, бюджеты, названия, метрики
- Если сведений для поля нет — поле остаётся пустой строкой
- Можно только переформулировать и структурировать сказанное пользователем
- Отвечать строго в JSON со всеми полями карточки из docs/CONTRACT.md
```

### Реализация

**Промпт для Codex:**

```
Реализуй в core/ai.py настоящие вызовы модели.

Добавь внутреннюю функцию _call_model(system_prompt, user_content) -> str:
- Клиент OpenAI, ключ и модель из переменных окружения OPENAI_API_KEY и OPENAI_MODEL
- Таймаут из REQUEST_TIMEOUT_SECONDS, по умолчанию 30
- При любой ошибке (нет ключа, сеть, таймаут, ошибка API) выбрасывает LLMError

analyze_draft:
1. Вызывает модель с ANALYZE_PROMPT
2. Парсит JSON из ответа; если модель обернула его в ``` — снять обёртку
3. Проверяет: questions непустой список, у каждого есть key и question,
   key входит в список семи допустимых ключей. Невалидные отбрасывает
4. Если после фильтрации вопросов меньше трёх — дополняет из fallback-набора
5. Возвращает {"questions": [...], "missing": [...], "source": "ai"}
6. При LLMError или неразборном JSON — возвращает fallback-результат
   с "source": "fallback", не падает

build_card аналогично, плюс критично:
- После разбора ответа модели прогони проверку: каждое непустое поле карточки
  должно иметь основание в исходном тексте. Реализуй простую проверку —
  если поле непустое, а ни одного значимого слова из него нет ни в черновике,
  ни в ответах пользователя, поле обнуляется в пустую строку.
- Поля карточки строго из docs/CONTRACT.md, лишние отбрасываются
```

Пункт про обнуление — это прямая защита от выдуманных фактов, самый проверяемый
пункт критерия AI-функции.

**Готово когда:** на слабом черновике получаешь ≥3 осмысленных вопроса; после
ответов собирается карточка, где незаполненные поля остались пустыми.

## 100–165 минут · Fallback и надёжность

**Промпт для Codex:**

```
Добавь в core/ai.py детерминированный fallback без модели.

_fallback_analyze(draft, industry): по ключевым словам определяет, какие из семи
показателей упомянуты в черновике, остальные считает недостающими и берёт
для них готовые вопросы из словаря FALLBACK_QUESTIONS в core/prompts.py.
Всегда возвращает минимум 3 вопроса.

_fallback_build_card(draft, answers): черновик кладёт в context, каждый ответ —
в поле с соответствующим key. Ничего не выдумывает.

Оба помечают результат "source": "fallback".

Добавь тест-режим: если переменная окружения AI_MODE=fallback, функции
работают без модели вообще. Это нужно для демонстрации при отсутствии интернета.
```

`AI_MODE=fallback` — твоя страховка на защите: если сеть упадёт, сквозной
сценарий всё равно проходит целиком.

Затем проверь обработку ошибок: убери ключ, отправь запрос — должен прийти
`source: fallback`, а не падение.

## 225–270 минут · Устойчивость

Проверь и почини:

- Модель вернула не JSON → fallback, не падение
- Модель вернула JSON с лишними полями → лишние отброшены
- Черновик на казахском или английском → вопросы на языке черновика
- Очень короткий черновик («нужен сайт») → всё равно ≥3 вопроса
- Очень длинный черновик → обрезается до 4000 символов с предупреждением

## 270–300 минут · Демо

Подготовь для защиты:

1. **Слабый черновик** — 1–2 предложения, по которому рейтинг будет низким.
   Например: «Хотим как-то автоматизировать работу с заявками, сейчас всё в Excel».
2. **Ответы на вопросы** — готовые, чтобы не придумывать на сцене.
3. Прогони цепочку дважды: результат должен быть стабильным.

Для README дай участнику 3 два абзаца: как работает AI-функция (вход, промпт,
выход, обработка ошибок) и как устроена защита от выдуманных фактов.
