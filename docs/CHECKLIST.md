# Чек-лист Sana

Проверять по фактическому проекту на контрольных точках из `docs/PLAN.md`. Чек-лист следует PDF конкретного кейса, а не общей шкале из руководства другого трека.

## Черновик и карточка

- [x] Свободный ввод черновика и темы/отрасли
- [x] Система определяет недостающие сведения
- [x] Не менее трёх уместных вопросов
- [x] Карточка содержит название, контекст, потребность, пользователей, данные/материалы, ограничения, ожидаемый результат, критерии успеха, контакт и формат взаимодействия
- [x] Карточку можно редактировать
- [x] Непредоставленные пользователем факты остаются пустыми
- [x] Публикация происходит только после явного подтверждения человека

## Рейтинг и геймификация

- [x] Рейтинг в пределах 0–100
- [x] Видны семь показателей, заработанные и максимальные баллы
- [x] Видны недостающие сведения и подсказки с потенциальными баллами
- [x] Рейтинг пересчитывается при редактировании/подтверждённом дополнении
- [x] Границы уровней: 0–39, 40–69, 70–89, 90–100
- [x] Порядок каталога учитывает рейтинг
- [x] Низкий рейтинг не скрывает опубликованную задачу и не блокирует предложение

## Каталог и предложения

- [x] Общий список показывает все опубликованные задачи
- [x] Есть сортировка по рейтингу
- [x] Есть фильтры по теме и уровню готовности
- [x] Любая команда может отправить идею, план, срок и ссылку
- [x] Ограничения на число предложений нет
- [x] Бизнес видит предложения и вручную выбирает или отклоняет каждое
- [x] Можно выбрать несколько или ни одной команды
- [x] Система не назначает исполнителей автоматически

## Прогресс выбранной команды

- [x] Принятая команда прикладывает фактический результат и ссылку-доказательство по этапу
- [x] Бизнес явно подтверждает или отклоняет каждый отчёт; решение выносится один раз
- [x] Баллы появляются только за подтверждённый отчёт; табло суммирует баллы команд
- [x] Размер 10 баллов за этап обозначен в README как MVP-допущение, а не требование PDF
- [ ] Уточнить у организаторов точное правило начисления баллов за этап

## AI, данные и надёжность

- [x] Минимум одна содержательная AI-функция использует реальный API, когда он доступен
- [x] Промпт и вход/выход можно показать жюри
- [x] Некорректный/недоступный AI даёт видимый детерминированный fallback
- [x] Валидируются пустые и слишком длинные поля, типы и значения решений
- [x] Отсутствующий или некорректный JSON не ломает запуск и не стирает рабочие данные
- [x] Есть минимум 5 черновиков, 5 карточек, 5 профилей команд и 5 предложений
- [x] Используются синтетические данные без реальных компаний и персональных данных
- [x] Новые зависимости, если есть, описаны в `requirements.txt`

## Результаты сдачи

- [x] В репозитории есть `.env.example`, нет `.env` и ключей
- [ ] В каждом отчётном часе есть содержательный Git-прогресс
- [x] Свежий clone устанавливает зависимости и запускается по README (проверено в отдельном временном окружении Python 3.12)
- [x] README содержит архитектуру, технологический стек, AI/данные, формулу рейтинга, правила каталога, запуск, тестовые сценарии и ограничения
- [x] Сторонние шаблоны, библиотеки, blueprint-ы и датасеты раскрыты
- [x] Весь пользовательский путь показан в работающем MVP, не на слайдах
- [ ] Пятиминутная демонстрация отрепетирована
- [ ] Решение отправлено через страницу трека
