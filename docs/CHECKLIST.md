# Чек-лист Sana

Проверять по фактическому проекту на контрольных точках из `docs/PLAN.md`. Чек-лист следует PDF конкретного кейса, а не общей шкале из руководства другого трека.

## Черновик и карточка

- [ ] Свободный ввод черновика и темы/отрасли
- [ ] Система определяет недостающие сведения
- [ ] Не менее трёх уместных вопросов
- [ ] Карточка содержит название, контекст, потребность, пользователей, данные/материалы, ограничения, ожидаемый результат, критерии успеха, контакт и формат взаимодействия
- [ ] Карточку можно редактировать
- [ ] Непредоставленные пользователем факты остаются пустыми
- [ ] Публикация происходит только после явного подтверждения человека

## Рейтинг и геймификация

- [ ] Рейтинг в пределах 0–100
- [ ] Видны семь показателей, заработанные и максимальные баллы
- [ ] Видны недостающие сведения и подсказки с потенциальными баллами
- [ ] Рейтинг пересчитывается при редактировании/подтверждённом дополнении
- [ ] Границы уровней: 0–39, 40–69, 70–89, 90–100
- [ ] Порядок каталога учитывает рейтинг
- [ ] Низкий рейтинг не скрывает опубликованную задачу и не блокирует предложение

## Каталог и предложения

- [ ] Общий список показывает все опубликованные задачи
- [ ] Есть сортировка по рейтингу
- [ ] Есть фильтры по теме и уровню готовности
- [ ] Любая команда может отправить идею, план, срок и ссылку
- [ ] Ограничения на число предложений нет
- [ ] Бизнес видит предложения и вручную выбирает или отклоняет каждое
- [ ] Можно выбрать несколько или ни одной команды
- [ ] Система не назначает исполнителей автоматически

## Прогресс выбранной команды

- [ ] Принятая команда прикладывает фактический результат и ссылку-доказательство по этапу
- [ ] Бизнес явно подтверждает или отклоняет каждый отчёт; решение выносится один раз
- [ ] Баллы появляются только за подтверждённый отчёт; табло суммирует баллы команд
- [ ] Размер 10 баллов за этап явно обозначен как MVP-допущение, так как PDF не устанавливает сумму; запросить у организаторов точное правило

## AI, данные и надёжность

- [ ] Минимум одна содержательная AI-функция использует реальный API, когда он доступен
- [ ] Промпт и вход/выход можно показать жюри
- [ ] Некорректный/недоступный AI даёт видимый детерминированный fallback
- [ ] Валидируются пустые и слишком длинные поля, типы и значения решений
- [ ] Отсутствующий или некорректный JSON не ломает запуск
- [ ] Есть минимум 5 черновиков, 5 карточек, 5 профилей команд и 5 предложений
- [ ] Используются синтетические данные без реальных компаний и персональных данных
- [ ] Новые зависимости, если есть, описаны в `requirements.txt`

## Результаты сдачи

- [ ] Код находится в выданном платформой командном GitHub-репозитории
- [ ] В репозитории есть `.env.example`, нет `.env` и ключей
- [ ] В каждом отчётном часе есть содержательный Git-прогресс
- [ ] Свежий clone устанавливает зависимости и запускается строго по README
- [ ] README содержит архитектуру, технологический стек, AI/данные, формулу рейтинга, правила каталога, запуск, тестовые сценарии и ограничения
- [ ] Сторонние шаблоны, библиотеки, blueprint-ы и датасеты раскрыты
- [ ] Весь пользовательский путь показан в работающем MVP, не на слайдах
- [ ] Пятиминутная демонстрация отрепетирована
- [ ] Решение отправлено через страницу трека
