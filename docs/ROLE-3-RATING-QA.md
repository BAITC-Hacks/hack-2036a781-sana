**Тестовые данные.** Кейс требует минимальный объём: 5 черновиков, 5 карточек,

proposals.json — 5 предложений от разных команд к разным задачам:

demo.json — один слабый черновик для кнопки «Демо-пример» и готовые ответы

Данные синтетические, правдоподобные, на русском. Реальных компаний и людей нет.

## 100–165 минут · Настоящая формула рейтинга

Главный час дня — 25 баллов.

**Промпт для Codex:**

```
Реализуй настоящую calculate_rating в core/rating.py по docs/CONTRACT.md.

Показатели и веса:
context_need 20 (поля context, need), data_materials 20 (data_materials),
expected_result 15, success_criteria 15, constraints 10, users 10,
business_link 10 (поля contact, interaction_format).

Правила начисления:
- Поле считается заполненным, если после strip длина не меньше 15 символов.
  Строки короче — не засчитываются: это защита от «ок», «да», «-».
- Показатель из одного поля: заполнено — полный вес, нет — 0.
- Показатель из двух полей: оба — полный вес, одно — половина веса (округление вниз).
- score — сумма, максимум 100.

Возвращает breakdown со всеми семью показателями (включая незаполненные, с earned 0),
missing — ключи незаполненных, tips — подсказки для каждого недостающего показателя
в формате "Добавьте <что именно> — это +N баллов", отсортированные по убыванию веса.

Тексты подсказок вынеси в словарь TIPS в начале файла.

Функция чистая: без обращений к сети, файлам и времени.
```

**Промпт для Codex (тесты):**

```
Создай tests/test_rating.py — тщательные тесты формулы:

1. Полностью заполненная карточка -> score 100, level "priority", missing пуст
2. Полностью пустая -> score 0, level "draft", missing содержит все семь ключей
3. Заполнен только context, need пуст -> context_need даёт 10, а не 20
4. Поле из трёх символов -> не засчитывается
5. Границы уровней: 39->draft, 40->working, 69->working, 70->ready,
   89->ready, 90->priority, 100->priority
6. breakdown всегда содержит ровно 7 показателей
7. Сумма max в breakdown равна 100
8. tips отсортированы по убыванию веса
9. calculate_rating(None) и calculate_rating("строка") не падают
10. Добавление поля только увеличивает score, никогда не уменьшает
```

Пункт 10 важен: жюри на защите увидит рост рейтинга, и он не должен «прыгать».

**Готово когда:** `pytest -q` зелёный, и ты вручную проверил: дописываешь поле —
балл растёт ровно на его вес.
