# Участник 2 — Интерфейс и сквозной сценарий

Твоя папка: `app/`.
Ты закрываешь: сквозной сценарий (20) + каталог и отклики (15) = **35 баллов**.

Что проверяют: черновик проходит публикацию, отклик и решение бизнеса; все задачи
доступны всем; бизнес выбирает команду вручную. На защите все переходы работают
в MVP, а не на слайдах.

**Главное правило:** ты не ждёшь ни AI, ни рейтинг. Оба коммитят заглушки в первые
30 минут, и ты строишь весь сценарий на них. Настоящая логика подключится сама.

**Три экрана:** Бизнес · Каталог · Мои задачи. Переключение ролью в шапке, без
регистрации — она исключена ограничением объёма кейса.

## 0:20–0:30 · Каркас

**Промпт для Codex:**

```
Создай каркас FastAPI в app/.

app/main.py:
- FastAPI-приложение, загрузка .env через python-dotenv
- GET /api/health -> {"status": "ok"}
- GET / -> отдаёт app/static/index.html
- Статика из app/static/
- Единый формат ответа: {"ok": true, "data": {...}} либо
  {"ok": false, "error": {"code": ..., "message": ...}}, HTTP всегда 200
- Глобальный обработчик исключений, возвращающий этот формат с кодом internal_error

Создай app/static/index.html с шапкой, переключателем роли
(Бизнес / Студенческая команда) и тремя пустыми секциями-экранами.
```

Коммить сразу.

## 30–100 минут · Экран «Бизнес»

Это ядро сценария: черновик → вопросы → карточка → подтверждение.

**Промпт для Codex (роуты):**

```
Добавь в app/main.py роуты конструктора задачи по docs/CONTRACT.md:

POST /api/analyze    -> core.ai.analyze_draft(draft, industry)
POST /api/build-card -> core.ai.build_card(draft, answers)
POST /api/rating     -> core.rating.calculate_rating(card)
POST /api/tasks      -> считает рейтинг, ставит status="published", core.store.save_task
GET  /api/tasks      -> core.store.load_tasks с фильтрами industry, level и сортировкой
GET  /api/tasks/{id} -> core.store.get_task, при отсутствии error.code="not_found"
PUT  /api/tasks/{id} -> обновляет карточку и пересчитывает рейтинг

Роуты не содержат бизнес-логики: только валидация входа, вызов функции модуля
и обёртка ответа. Внутрь core/ не лезь, используй только публичные функции.
```

**Промпт для Codex (экран):**

```
Создай экран «Бизнес» в app/static: index.html + app.js + styles.css.

Шаг 1. Поле для черновика (textarea), выбор отрасли, кнопка «Проанализировать».
Шаг 2. После ответа /api/analyze — список вопросов, под каждым поле для ответа.
       Кнопка «Собрать карточку».
Шаг 3. После /api/build-card — форма карточки со всеми полями из контракта.
       Все поля редактируемые. Пустые поля визуально помечены как незаполненные.
Шаг 4. Кнопка «Опубликовать задачу» — вызывает POST /api/tasks.
       Публикация только по нажатию, никакой автопубликации.

Шаги показываются последовательно, предыдущие остаются видимыми.
Без внешних библиотек и CDN, только собственный CSS.
```

**Готово когда:** проходишь три шага и получаешь опубликованную задачу — пока с
пустым рейтингом от заглушки.

## 100–165 минут · Панель рейтинга

Это витрина самого весомого критерия (25 баллов). Рейтинг должен быть **виден**,
а не спрятан в коде.

**Промпт для Codex:**

```
Добавь к форме карточки боковую панель рейтинга.

Содержимое:
1. Крупная цифра — score из 100 и подпись уровня готовности
   (Черновик / Рабочая / Готовая / Приоритетная), цвет по уровню
2. Разбивка: список всех семи показателей из breakdown, у каждого
   "заработано из максимума" и отметка, заполнен ли он
3. Блок «Что повысит рейтинг» — список tips, каждый пункт с указанием,
   сколько баллов добавит
4. Полоса прогресса от 0 до 100

Живой пересчёт: при изменении любого поля карточки с задержкой 400 мс
отправляется POST /api/rating и панель обновляется. Изменение цифры плавно
анимируется, чтобы рост рейтинга был заметен на демонстрации.
```

Пункт про анимацию не косметика: на защите вы показываете именно **рост рейтинга**
при дополнении задачи.

**Готово когда:** дописываешь поле — цифра растёт на глазах, подсказки меняются.

## 165–225 минут · Каталог, отклики, решение бизнеса

**Промпт для Codex (роуты):**

```
Добавь роуты откликов по docs/CONTRACT.md:

GET  /api/teams
POST /api/tasks/{id}/proposals   -> core.store.save_proposal
GET  /api/tasks/{id}/proposals   -> core.store.load_proposals
POST /api/proposals/{id}/decision -> core.store.update_proposal_status
GET  /api/recommendations?team_id=...

Критично: отклик принимается для задачи с любым рейтингом, включая 0.
Статус предложения меняется только через явный вызов decision.
Никакой логики автоматического выбора команды нигде быть не должно.
```

**Промпт для Codex (экран «Каталог»):**

```
Экран «Каталог» в app/static:

- Карточки всех опубликованных задач, по умолчанию отсортированы по рейтингу убыв.
- На карточке: название, отрасль, балл, метка уровня цветом, краткий контекст
- Сортировка: по рейтингу / по дате
- Фильтры: отрасль, уровень готовности
- Задачи с низким рейтингом отображаются наравне с остальными, просто ниже
  и с меткой «Требует уточнения». Не скрывать и не блокировать
- Клик по задаче — подробный просмотр: вся карточка и разбивка рейтинга
- В режиме «Студенческая команда»: выбор команды из списка и форма отклика
  (идея, план, срок, ссылка), кнопка «Отправить предложение»
- После отправки — подтверждение и счётчик откликов на задаче
```

**Промпт для Codex (экран «Мои задачи»):**

```
Экран «Мои задачи» для режима «Бизнес»:

- Список опубликованных задач с числом предложений
- По клику — список предложений: команда, идея, план, срок, ссылка
- У каждого предложения две кнопки: «Выбрать» и «Отклонить»
- Статус отображается меткой: Новое / Выбрано / Отклонено
- Можно выбрать несколько команд или ни одной — ограничений нет
- Решение отправляется только по клику пользователя
```

**Готово когда:** проходишь весь путь — опубликовал, переключился на команду,
откликнулся, вернулся в бизнес, выбрал. Это и есть сквозной сценарий на 20 баллов.

## 225–270 минут · Валидация и устойчивость

**Промпт для Codex:**

```
Добавь в app/static/app.js защиту:

- Пустой черновик: кнопка не отправляет запрос, подсказка под полем
- Черновик длиннее 4000 символов: счётчик и предупреждение
- Двойной клик: повторный запрос не уходит, пока идёт первый
- Индикатор «Обрабатываю...» на каждом запросе, снимается в любом случае
- ok === false: понятное сообщение в заметном блоке, не пустой экран
- Сервер недоступен: сообщение «Сервер недоступен», кнопка разблокирована
- Отклик без выбранной команды или с пустой идеей: не отправляется
- source === "fallback": ненавязчивая пометка «AI недоступен, базовый режим»
```

Последний пункт — честность, которую кейс прямо требует показать.
