# AGENTS.md

Инструкции для AI-агентов (Codex), работающих в этом репозитории.

## Проект

**Sana** — платформа геймификации постановки бизнес-задач.

Представитель бизнеса вводит черновик своей задачи. AI находит недостающие
сведения и задаёт не менее трёх уточняющих вопросов. Из ответов формируется
редактируемая карточка, которую человек подтверждает. Система считает рейтинг
готовности 0–100 и публикует задачу в общем каталоге на позиции по рейтингу.
Студенческие команды подают предложения, бизнес вручную выбирает.

Хакатон, 5 часов. План рассчитан на одного разработчика с Codex. Приоритет:
сквозной сценарий от черновика до решения бизнеса работает целиком. Ширина функций — вторична.

## Жёсткие правила предметной области

Нарушение любого пункта — прямая потеря баллов:

1. **AI не выдумывает факты.** В карточку попадает только то, что пользователь
   сообщил в черновике или в ответах на вопросы. Пустое поле остаётся пустым.
2. **Человек подтверждает.** Карточка редактируема и публикуется только после
   ручного подтверждения. Автопубликации нет.
3. **Команду выбирает бизнес.** Никакого автоматического назначения исполнителей.
   Система только показывает список предложений и кнопки «Выбрать» / «Отклонить».
4. **Низкий рейтинг ничего не скрывает.** Задача с 10 баллами видна в каталоге и
   принимает отклики наравне с остальными. Рейтинг влияет только на позицию и метку.
5. **Рейтинг прозрачен.** Всегда показываем разбивку по показателям и список того,
   что добавить для роста балла.
6. **Число откликов не ограничено.** Любая команда может откликнуться на любую задачу.

## Стек

- Python 3.11, FastAPI, Uvicorn
- Хранилище: JSON-файлы в `data/` (выбор MVP для пяти часов; PDF не требует базу данных)
- Фронтенд: React 19 + Vite; production-сборка лежит в `app/static/`
- OpenAI API — уточняющие вопросы и сборка карточки
- pytest

Не добавляй БД, Docker, полноценную авторизацию или real-time без необходимости:
полноценная реализация этих частей не нужна для пятичасового MVP. PDF прямо
исключает необходимость собственной ML-модели и векторной базы; JSON выбран как
самый простой способ хранения в этом стартовом наборе.

## Карта репозитория

```
core/ai.py         AI: анализ полноты, вопросы, сборка карточки  — участник 1
core/prompts.py    все промпты                                    — участник 1
core/rating.py     формула рейтинга и уровни готовности           — участник 3
core/store.py      чтение/запись JSON, работа с сущностями        — участник 3
app/main.py        FastAPI-роуты                                  — участник 2
frontend/src/      React-интерфейс: AI-чат, карточка, профили      — участник 2
app/static/        production-сборка React                         — участник 2
tests/             тесты                                          — участник 3
data/              задачи, команды, предложения                    — участник 3
docs/              контракт, план, роли
```

Указанные участники показывают командное разделение модулей. При работе одному
разработчику он отвечает за все папки, сохраняя границы модулей: `app/` вызывает
публичные функции `core/`, рейтинг остаётся чистым модулем, контракт не меняется
без обоснования.

## Контракт

Все структуры данных и эндпоинты зафиксированы в `docs/CONTRACT.md`.
Менять их нельзя без обоснования и явного обновления документации. `app/` не лезет внутрь `core/`,
вызывает только публичные функции модулей.

## Команды

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
npm install && npm run build
uvicorn app.main:app --port 8000
pytest -q
```

## Секреты

Ключи только в `.env`, он в `.gitignore`. Никогда не вставляй ключи в код, тесты,
промпты, README. В репозиторий идёт только `.env.example` с пустыми значениями.

## Стиль кода

- Ясные имена, без «умных» однострочников.
- Каждый вызов внешнего API — с таймаутом и в try/except.
- Весь пользовательский ввод валидируется: пустое, слишком длинное, неверный тип.
- `core/rating.py` — чистые функции без обращений к сети и файлам, чтобы их можно
  было тестировать изолированно.
- Если AI недоступен, `core/ai.py` возвращает детерминированный запасной результат
  (правила без модели) и явно помечает это в ответе полем `"source": "fallback"`.
  Это разрешено кейсом, но должно быть видно.

## Коммиты

`feat:` `fix:` `test:` `docs:` `chore:` + что сделано. Нужен минимум один
осмысленный коммит в каждый отчётный час.

## Чек-лист перед коммитом

1. `pytest -q` проходит
2. `uvicorn app.main:app` стартует
3. В диффе нет ключей и локальных путей
4. Новые импорты — в `requirements.txt`
5. Новые переменные окружения — в `.env.example`

## Чего не делать

- Не коммитить `.env`, `.venv/`, `__pycache__/`
- Не добавлять регистрацию, уведомления и загрузку файлов; AI-чат является интерфейсом конструктора задачи
- Не рефакторить то, о чём не просили
- Не изобретать поля карточки: их состав зафиксирован в контракте
