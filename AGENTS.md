# AGENTS.md

## Назначение проекта

Репозиторий содержит хакатонный MVP EduQuest AI. Продукт помогает бизнесу преобразовать сырое описание задачи в подтверждённую карточку с прозрачным рейтингом готовности, опубликовать её для студентов, получить предложения и вручную выбрать команду.

Главный приоритет любого AI-агента — сохранить работающий сквозной сценарий:

`черновик → уточняющие вопросы → редактируемая карточка → рейтинг → публикация → отклик → ручное решение бизнеса`.

## Перед началом изменения

1. Прочитайте `README.md` и `docs/HACKATHON_PLAN.md`.
2. Проверьте `git status` и не изменяйте незавершённую работу другого участника.
3. Определите владельца затрагиваемого модуля по таблице в README.
4. Если задача требует изменения общего контракта, сначала обновите или согласуйте типы в `types/index.ts`.
5. Не расширяйте объём задачи без прямого запроса пользователя.

## Архитектурные правила

- Используйте Next.js App Router и TypeScript со строгими типами.
- UI-компоненты не должны напрямую хранить или изменять глобальные массивы данных; используйте API/репозиторий.
- Бизнес-логика рейтинга находится только в `lib/rating.ts`.
- Схемы валидации находятся в `lib/validation.ts`.
- AI-провайдеры реализуют единый контракт из `lib/ai/types.ts`.
- Приложение обязано запускаться без внешнего AI API через `mock-provider`.
- Seed-данные хранятся в `data/seed.ts`; не размножайте тестовые данные по компонентам.
- Общие доменные типы хранятся в `types/index.ts`.
- Пользователь должен редактировать и подтверждать AI-результат до публикации.

## Инварианты кейса

- AI не добавляет факты, которых не сообщал пользователь. Неизвестное значение остаётся пустым.
- Генерируется минимум три уместных уточняющих вопроса.
- Рейтинг находится в диапазоне 0–100 и содержит расшифровку.
- Баллы начисляются только за заполненные и подтверждённые сведения.
- Все опубликованные задачи видны всем командам независимо от рейтинга.
- Низкий рейтинг не запрещает отклик.
- AI может рекомендовать задачи, но не выбирает и не назначает команду.
- Принять или отклонить предложение может только пользователь в роли бизнеса.
- Не использовать персональные и чувствительные признаки участников.

## Формула рейтинга

- контекст и потребность — 20;
- данные и материалы — 20;
- ожидаемый результат — 15;
- критерии успеха — 15;
- ограничения — 10;
- пользователи — 10;
- связь с бизнесом — 10.

Пороговые уровни: `0–39 draft`, `40–69 workable`, `70–89 ready`, `90–100 priority`.

Изменение формулы требует одновременного обновления тестов, README и UI-расшифровки.

## Работа с AI

Ожидаемый структурированный результат анализа должен включать:

```ts
type TaskAnalysis = {
  missingFields: TaskField[];
  questions: Array<{ field: TaskField; text: string }>;
  suggestedCard: Partial<TaskCard>;
};
```

- Валидируйте ответ провайдера до передачи в UI.
- При ошибке парсинга, таймауте или отсутствии ключа переключайтесь на детерминированный mock/fallback.
- Храните prompt отдельно от route handler, чтобы его можно было показать на защите.
- Не отправляйте секреты, контакты или чувствительные данные в логи.

## Границы модулей при параллельной работе

- Business UX: `app/business/**`, `components/business/**`.
- Core/API: `app/api/**`, `lib/**`, `types/**`, `data/**`, `tests/**`.
- Catalog UX: `app/catalog/**`, `components/catalog/**`, `components/shared/**`.
- Общие файлы (`package.json`, `app/layout.tsx`, глобальные стили, конфигурация) изменять минимально и явно сообщать команде.

Не выполняйте массовое форматирование и не переименовывайте каталоги во время параллельной разработки.

## Проверки

После изменения запускайте минимально достаточную проверку, а перед PR — полный набор:

```bash
pnpm lint
pnpm test
pnpm build
```

Для изменения пользовательского сценария дополнительно вручную пройдите затронутый путь. Для изменения рейтинга обязательно добавьте или обновите unit-тесты со значениями `0`, `39`, `40`, `69`, `70`, `89`, `90`, `100`.

## Definition of Done

Задача считается завершённой, когда:

- результат доступен через UI или API, как указано в задаче;
- входные данные валидируются, а ошибка понятна пользователю;
- нет выдуманных AI-данных;
- типы и контракты согласованы;
- проверки проходят;
- README обновлён, если изменился запуск, архитектура или сценарий;
- коммит ограничен одной логической темой.

## Формат отчёта AI-агента

В конце работы сообщите:

1. что изменено;
2. какие файлы затронуты;
3. какие проверки выполнены и их результат;
4. что осталось непроверенным;
5. есть ли риск конфликта с параллельной веткой.

Не заявляйте об успешной проверке, если команда фактически не запускалась.
