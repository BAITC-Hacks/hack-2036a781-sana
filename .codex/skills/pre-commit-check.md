# Skill: pre-commit-check

**Когда запускать:** на каждой контрольной точке (1:00, 2:00, 3:00, 4:00) и перед
финальной сдачей.

**Зачем:** за один прогон закрывает три критерия оценки — README (20), воспроизводимость
(20), надёжность и безопасность (15) — и снимает риск дисквалификации за ключи в
репозитории.

## Что делает агент по этому skill

Пройди по пунктам и по каждому дай вердикт: ОК или что именно не так.
Ничего не чини молча — сначала отчёт, потом правки по запросу.

1. **Секреты.** Проверь рабочее дерево и историю коммитов на API-ключи, токены и
   пароли. Ищи строки вида `sk-`, `nvapi-`, `Bearer `, а также присваивания
   переменным с `KEY`, `TOKEN`, `SECRET`, `PASSWORD`. Найденное — критично, сообщи сразу.

2. **Игнор-файлы.** `.env`, `.venv/`, `__pycache__/`, `*.pyc` присутствуют в
   `.gitignore` и не попали в индекс.

3. **Зависимости.** Каждый сторонний импорт в коде есть в `requirements.txt`.
   Назови импорты, которых там нет.

4. **Переменные окружения.** Каждая переменная, читаемая из кода через `os.getenv`,
   присутствует в `.env.example` и описана в README.

5. **Контракт.** `core/agent.py` экспортирует `run_agent(payload: dict) -> dict`,
   формат ответа совпадает с `docs/CONTRACT.md`. Отклонения перечисли.

6. **Заглушки.** Найди захардкоженные ответы, `return "заглушка"`, `TODO`, `FIXME`,
   закомментированные вызовы API. Перечисли с указанием файла и строки — это прямо
   снижает баллы по технической реализации.

7. **Обработка ошибок.** Каждый вызов внешнего API обёрнут в try/except и имеет
   таймаут. Назови вызовы без этого.

8. **README.** Все обязательные разделы на месте и не содержат незаполненных
   плейсхолдеров в угловых скобках. Раздел «Что реализовано» соответствует тому, что
   действительно есть в коде: перечисли расхождения в обе стороны.

9. **Команды запуска.** Команды из раздела «Установка и запуск» соответствуют
   реальной структуре проекта (имена модулей, пути, порт).

10. **Тесты.** `pytest -q` проходит. Если нет — покажи падающие тесты.

## Формат отчёта

Короткий список: пункт — вердикт — что править. Сначала критичное (секреты,
незапускаемость), затем остальное. Без похвалы и вводных.
