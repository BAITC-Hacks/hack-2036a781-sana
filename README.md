# Sana

Sana помогает бизнесу подготовить понятную практическую задачу для студентов. Бизнес описывает проблему, отвечает на уточняющие вопросы, проверяет карточку и сам публикует её. Команды видят общий каталог и отправляют предложения. Бизнес сам выбирает, с кем работать.

Это работающий веб MVP по кейсу HackAlem AI «Рейтинг качества бизнес задач и открытый выбор команд». Новый интерфейс собран на React: слева пользователь ведёт диалог с AI, справа в реальном времени видит редактируемую карточку и прозрачный рейтинг. Для запуска нужны Python 3.11+ и Node.js 20+.

## Что работает

1. Бизнес вводит свободное описание задачи. AI задаёт не меньше трёх вопросов о недостающих сведениях.
2. Из текста и ответов собирается карточка. Все поля можно изменить. AI не добавляет факты без подтверждения в исходном тексте.
3. Бизнес нажимает «Подтвердить и опубликовать». До этого задача не появляется в каталоге.
4. Рейтинг показывает баллы, пробелы и способы повысить оценку. После сохранения изменений он пересчитывается на сервере.
5. В общем каталоге видны все опубликованные задачи. Любая команда может отправить идею, план, срок и ссылку на прототип даже задаче с низким рейтингом.
6. Бизнес вручную принимает, отклоняет или оставляет без решения любое число предложений. Автоматического выбора команды нет.
7. Принятая команда может отправить результат этапа со ссылкой на доказательство. Баллы за этап появляются только после подтверждения бизнеса.
8. В профиле бизнеса сохраняются имя, компания и контакт для быстрого заполнения карточки. Студенты создают серверный профиль команды с интересами, навыками и технологиями.

При создании задачи или команды сервер выдаёт личный код доступа. Браузер сохраняет его для изменения своих данных. В меню «Доступ» код можно скопировать на своё другое устройство и там восстановить доступ. Регистрация не нужна.

## Рейтинг и каталог

Рейтинг относится к готовности **конкретной задачи**, а не к компании. Поле считается заполненным, если в нём не меньше 15 символов после удаления пробелов по краям. Это правило реализации, не отдельное условие организаторов. Два поля в одной строке таблицы дают половину баллов, если заполнено только одно. Итоговый рейтинг опубликованной задачи сохраняется после ручного подтверждения карточки.

| Показатель | Поля карточки | Максимум |
| --- | --- | ---: |
| Контекст и потребность | Контекст, потребность | 20 |
| Данные и материалы | Данные и материалы | 20 |
| Ожидаемый результат | Ожидаемый результат | 15 |
| Критерии успеха | Критерии успеха | 15 |
| Ограничения | Ограничения | 10 |
| Пользователи | Пользователи | 10 |
| Связь с бизнесом | Контакт, формат взаимодействия | 10 |

Итого — от 0 до 100. Уровни: **0–39** — требует уточнения, **40–69** — рабочая, **70–89** — готовая, **90–100** — приоритетная. Каталог по умолчанию сортируется по баллам от большего к меньшему; при равных баллах сохраняется порядок добавления. Можно выбрать сортировку по дате, а также фильтры по теме и уровню готовности. Низкий балл меняет метку и позицию, но не скрывает задачу и не запрещает отклик.

Баллы за результат команды — отдельная механика. MVP начисляет **10 баллов за подтверждённый этап**. Кейс требует начислять их после подтверждения, но не задаёт точную величину; число 10 — наше правило для MVP.

## Установка и запуск

Откройте терминал в корне проекта. Используйте Python 3.11 или новее.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
npm install
npm run build
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В Windows используйте `py -3.11 -m venv .venv`, затем `.venv\Scripts\activate` и `copy .env.example .env`. Команда `npm run build` собирает React в `app/static/`. Откройте `http://127.0.0.1:8000` в браузере. Для разработки интерфейса можно отдельно выполнить `npm run dev` и открыть `http://127.0.0.1:5173`.

В `.env` можно указать `OPENAI_API_KEY`. Тогда Sana обращается к OpenAI API. Если ключа или доступа к API нет, сценарий остаётся доступен с локальными вопросами и сборкой карточки из введённых фактов. Для гарантированного локального режима установите `AI_MODE=fallback`. `.env` исключён из Git; ключ нельзя вставлять в исходный код, README или коммиты.

Новые рабочие записи хранятся в `.sana-data/`, которая создаётся при запуске и не входит в Git. Путь можно изменить через `SANA_DATA_DIR` в окружении. Папка `data/` содержит отдельные синтетические примеры: 5 черновиков, 5 карточек, 5 профилей команд и 5 предложений. Эти записи не выдаются за реальные заявки и не подмешиваются в пустой рабочий каталог.

## Как проверить основной сценарий

Начните с пустой `.sana-data/` или свежего клона. Эти шаги не требуют заранее подготовленного ответа модели.

1. На экране бизнеса напишите коротко: «Нужно сократить время проверки домашних работ по Python». Выберите тему и нажмите «Найти, чего не хватает».
2. Ответьте минимум на три появившихся вопроса. Нажмите «Собрать карточку». Заполните пустые поля: доступные обезличенные примеры, ожидаемый результат, измеримые критерии, ограничения, пользователей и контакт. Проверьте рост рейтинга, затем нажмите «Подтвердить и опубликовать».
3. Откройте каталог: новая задача появилась на месте по рейтингу. Убедитесь, что фильтр по теме и уровню работает.
4. Переключитесь на «Студенческая команда». Создайте профиль команды, откройте задачу и отправьте идею, план, срок и ссылку вида `https://example.org/prototype`.
5. Вернитесь к бизнесу и откройте «Мои задачи». Найдите предложение и вручную нажмите «Выбрать» либо «Отклонить». Для проверки прогресса выберите предложение.
6. Снова откройте роль команды: отправьте результат этапа и ссылку на доказательство. Вернитесь к бизнесу и подтвердите этап. На табло команды появятся 10 баллов.

Данные остаются после перезагрузки страницы и перезапуска одного процесса сервера. Для технической проверки выполните `python -m pytest -q`. Короткий ответ сервера доступен по `GET /api/health`.

## Как устроен проект

| Часть | Назначение |
| --- | --- |
| `app/main.py` | FastAPI: запросы, проверка ввода, права на изменения, ответы API |
| `frontend/src/` | React-интерфейс: AI-чат, живая карточка, каталог, отклики и профили |
| `app/static/` | Production-сборка React, которую раздаёт FastAPI |
| `core/ai.py`, `core/prompts.py` | OpenAI Chat Completions, проверка ответа модели и локальный резервный режим |
| `core/rating.py` | Детерминированная формула рейтинга |
| `core/store.py` | Чтение и запись рабочих JSON файлов |
| `data/` | Синтетические примеры для кейса и проверок |
| `tests/` | Проверки рейтинга и основных API переходов |

Стек: Python, FastAPI, Uvicorn, OpenAI Python SDK, React 19, Vite, pytest и httpx. Во время работы приложение обращается к OpenAI только при настроенном ключе и выключенном `AI_MODE=fallback`. NVIDIA, сторонние учебные данные и готовые шаблоны в работающей логике не используются. Codex применялся как инструмент разработки, а не как сервис, от которого зависит запуск сайта.

Вызов AI получает черновик, тему и язык; ответом служит JSON со списком вопросов и недостающих сведений. Второй вызов получает черновик и ответы и возвращает JSON с полями карточки. Промпты доступны в `core/prompts.py`, структура входа и выхода — в `docs/CONTRACT.md`. Если модель недоступна, вернула некорректный JSON или меньше трёх подходящих вопросов, включается локальный режим. Текст поля принимается только при точном совпадении с фрагментом исходного ввода.

## Ограничения

Код доступа хранится в браузере. Сохраните копию через меню «Доступ» до очистки браузера: без кода восстановить права нельзя. JSON хранилище защищает одновременные записи блокировкой, но для публичного многопользовательского размещения всё ещё нужны резервные копии и постоянный сервер с HTTPS. Публичная развёрнутая версия пока не указана. Локальный запуск и проверка сценария доступны по инструкции выше.
