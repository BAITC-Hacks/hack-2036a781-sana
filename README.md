# EduQuest AI

EduQuest AI — MVP образовательной платформы, которая превращает сырой запрос бизнеса в понятную практическую задачу для студенческих команд. Система задаёт уточняющие вопросы, формирует редактируемую карточку, рассчитывает рейтинг готовности задачи и публикует её в общем каталоге. Студенты отправляют предложения, а представитель бизнеса вручную принимает или отклоняет их.

> Статус: подготовлена архитектура и командный план. Функции ниже являются целевым объёмом MVP для хакатона.

## Главный сценарий

1. Бизнес вводит короткое, неполное описание задачи.
2. AI-анализ находит пробелы и формирует минимум три уточняющих вопроса.
3. Ответы преобразуются в редактируемую карточку задачи.
4. Пользователь подтверждает карточку и видит рейтинг от 0 до 100, расшифровку и рекомендации.
5. После дополнения карточки рейтинг пересчитывается, а задача публикуется в каталоге.
6. Студенческая команда выбирает задачу и отправляет идею, план, срок и ссылку на прототип.
7. Бизнес вручную принимает или отклоняет предложение.

## Возможности MVP

### Обязательно

- свободный ввод первоначального описания;
- анализ полноты и не менее трёх уточняющих вопросов;
- редактируемая карточка с ручным подтверждением;
- прозрачный рейтинг 0–100 с детализацией начисления;
- рекомендации по повышению рейтинга и пересчёт после изменений;
- общий каталог, сортировка по рейтингу, фильтры по теме и готовности;
- форма отклика команды: идея, план, срок, ссылка;
- ручные действия бизнеса «Принять» и «Отклонить»;
- минимум пять задач, пять команд и пять предложений в тестовых данных;
- обработка пустого ввода и некорректного ответа AI;
- локальная AI-заглушка, если внешний API недоступен.

### Дополнительно, только после завершения сквозного сценария

- рекомендации задач командам по навыкам;
- анимация роста рейтинга и значки уровней готовности;
- сохранение состояния в `localStorage` или SQLite;
- журнал изменения рейтинга;
- начисление баллов выбранной команде за подтверждённый прогресс;
- экспорт карточки в JSON.

Не входят в MVP: полноценная регистрация, чат, уведомления, календарь, файловое хранилище, мобильная адаптация, собственная ML-модель и автоматический выбор команды.

## Формула рейтинга

| Раздел | Максимум |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |
| **Всего** | **100** |

Уровни готовности: `0–39` — черновик, `40–69` — рабочая, `70–89` — готовая, `90–100` — приоритетная. Низкий рейтинг не скрывает задачу и не запрещает отклик.

## Технологии

- Next.js (App Router), React, TypeScript;
- Tailwind CSS;
- Route Handlers для API;
- Zod для проверки входных данных;
- Vitest для тестирования формулы рейтинга;
- in-memory repository и синтетические seed-данные для надёжной локальной демонстрации;
- AI-адаптер с режимами `mock` и внешним провайдером через переменные окружения.

Выбор Next.js позволяет держать интерфейс и API в одном репозитории. Для пятичасового хакатона база данных не обязательна: приоритет — устойчивый сквозной сценарий.

## Запуск

Требования: Node.js 20+ и pnpm 9+.

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

На Windows PowerShell вместо `cp`:

```powershell
Copy-Item .env.example .env.local
```

Открыть [http://localhost:3000](http://localhost:3000).

Проверки перед объединением изменений:

```bash
pnpm lint
pnpm test
pnpm build
```

По умолчанию приложение должно работать с `AI_PROVIDER=mock`. Подключение внешнего провайдера не должно быть условием запуска демонстрации.

## Распределение команды

| Участник | Зона ответственности | Основные файлы |
|---|---|---|
| 1 — Business UX | ввод, вопросы, редактирование карточки, экран рейтинга | `app/business/**`, `components/business/**` |
| 2 — Core/API | типы, рейтинг, AI-адаптер, validation, API, seed | `lib/**`, `types/**`, `data/**`, `app/api/**`, `tests/**` |
| 3 — Catalog UX | каталог, фильтры, карточка задачи, отклик, выбор бизнеса | `app/catalog/**`, `components/catalog/**`, `components/shared/**` |

Общие файлы (`package.json`, layout, глобальные стили, README) изменяет только назначенный интегратор либо участник после согласования в командном чате.

## Совместная работа через GitHub

- `main` всегда должна запускаться и использоваться для демонстрации.
- Каждый работает в короткой ветке: `feat/business-flow`, `feat/core-api`, `feat/catalog-flow`.
- Перед началом работы: `git pull --rebase origin main`.
- Коммиты небольшие и содержательные: `feat(rating): add transparent score breakdown`.
- Пушить после каждого работающего вертикального фрагмента, ориентировочно каждые 20–30 минут.
- Pull request открывать рано как draft; объединять после быстрой проверки владельцем соседнего модуля.
- Перед merge автор обновляет ветку от `main`, запускает lint/test и вручную проверяет затронутый сценарий.
- Не форматировать весь проект и не перемещать чужие файлы во время параллельной работы.
- Конфликты разрешают совместно автор конфликтующего файла и интегратор, а не случайным выбором одной версии.

## Сценарий демонстрации — до 5 минут

1. Ввести слабое описание: «Хотим улучшить работу школьной столовой».
2. Показать минимум три релевантных уточняющих вопроса.
3. Ответить на вопросы и получить заполненную, но редактируемую карточку.
4. Показать низкий рейтинг, недостающие поля и объяснение баллов.
5. Добавить данные и измеримые критерии успеха; показать рост рейтинга.
6. Подтвердить и опубликовать задачу.
7. Открыть каталог в роли студенческой команды и показать позицию задачи.
8. Отправить предложение с идеей, планом, сроком и ссылкой.
9. Вернуться в роль бизнеса и вручную принять предложение.
10. Коротко показать prompt, JSON-вход/выход AI и fallback на случай ошибки.

## Критерий готовности проекта

Проект готов к сдаче, если после чистой установки одна команда запускает приложение, а подготовленный демонстрационный сценарий полностью проходит без ручного изменения данных, перезапуска сервера и перехода к слайдам.

Подробный почасовой план и интеграционные точки находятся в [`docs/HACKATHON_PLAN.md`](docs/HACKATHON_PLAN.md).
