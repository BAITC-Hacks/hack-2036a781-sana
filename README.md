# Sana

Подготовительный набор для кейса AI Sana «Рейтинг качества бизнес-задач и открытый выбор команд».

## Статус

Реализован локально проверяемый MVP Sana по основному сценарию кейса, с интерфейсом на русском, казахском и английском и исходным логотипом Sana. Git remote настроен на командный репозиторий, однако GitHub отвечает `Repository not found`, поэтому отправить коммиты пока нельзя. Нужен доступ к репозиторию или актуальный адрес.

## Цель проекта

Планируемый продукт поможет представителю бизнеса превратить неполный черновик в подтверждённую карточку практической задачи. Система будет задавать уточняющие вопросы, показывать прозрачный рейтинг готовности и открывать задачу в общем каталоге. Студенческие команды подают предложения, а бизнес выбирает вручную.

## Реализованный сценарий

Черновик → минимум три уточняющих вопроса → редактируемая карточка → ручное подтверждение → рейтинг и открытый каталог → предложение команды → ручное решение бизнеса.

AI использует OpenAI Chat Completions при наличии `OPENAI_API_KEY`; `AI_MODE=fallback`, отсутствие ключа или ошибка провайдера включает детерминированный fallback. Сведения, которых пользователь не сообщал, остаются пустыми. Низкий рейтинг меняет позицию и метку задачи, но не скрывает её и не запрещает отклик. Бизнес принимает решение вручную; команды, предложение или прогресс не выбираются автоматически.

## Критерии оценки кейса

| Критерий | Баллы |

## Уже реализовано

- AI-анализ черновика, не менее трёх вопросов, сборка редактируемой карточки только из проверенных фактов и fallback.
- Рейтинг 0–100 по семи критериям с разбивкой, пропусками и подсказками; серверный пересчёт.
- Явная публикация в открытый каталог, фильтры и сортировка; низкий балл не закрывает отклик.
- Предложения команд и ручные решения бизнеса.
- Для выбранной команды: отчёт о фактическом результате с доказательством; бизнес подтверждает или отклоняет этап.
- Демо-табло считает только подтверждённые этапы. MVP начисляет 10 очков за этап; PDF требует очки после подтверждения, но не задаёт их размер, поэтому это правило явно обозначено как проектное допущение.
- JSON-хранилище с синтетическими примерами; главная страница на HTML/CSS/JavaScript без CDN.

Ограничения: учётные записи и авторизация не входят в MVP, поэтому пользователь выбирает команду из списка вручную; JSON-хранилище рассчитано на демонстрационное развёртывание с одним процессом; официальную величину прогресс-очков следует сверить с организаторами.

## Локальный запуск

Требуются Python 3.11+ и Git.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и добавьте `OPENAI_API_KEY`, если хотите включить реальный AI. Без ключа fallback работает локально.

```bash
uvicorn app.main:app --port 8000
```

Откройте `http://localhost:8000`. Проверки: `pytest -q`, `python -m compileall -q app core tests`. Основные API и прогресс-поток покрыты тестами в `tests/`. Данные в `data/` синтетические. Перед сдачей перенесите результат в репозиторий, выданный платформой, после получения доступа и проверьте чистый clone.
